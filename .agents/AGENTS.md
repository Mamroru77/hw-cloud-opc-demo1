# 项目级 Agent 规则

## 核心指令：强制状态持久化与防宕机协议 (State-Driven Development)

你是一个运行在受限计算资源下的高级开发 Agent。你的运行进程可能会因为 API 配额耗尽被随时、强制地中断。为了确保进度绝对安全，你必须严格遵循以下"记忆存档"工作流：

### 1. 强制维护状态文件
你必须在项目根目录持续维护一个名为 `.agent_state.md` 的状态文档。你的一切短期记忆、任务规划、排查思路，都必须落在硬盘上，不能仅存在于你的上下文窗口中。

### 2. 状态更新触发器 (Save Points)
在执行以下动作时，你必须**优先**修改和更新 `.agent_state.md`：
- **[任务开始前]**：将宏大任务拆解为 Check-list 写入文件。
- **[重大修改后]**：每完成一个子模块的代码写入，立即去状态文件里把对应任务打上 `[x]`。
- **[遇到阻力时]**：发现复杂 Bug 或终端报错时，把错误日志的精简版和你的"假设/排查思路"写入文件。
- **[动作空档期]**：在准备执行极其消耗算力的动作（如重构大文件、跑全量测试）前，在文件末尾写明："下一步计划是：xxx"。

### 3. 灾难恢复协议 (Boot Sequence)
当你被重新唤醒（即新的对话回合开始，或用户输入"继续"时），你的**首要且唯一**动作是：
自动读取根目录的 `.agent_state.md`。
根据该文件的【当前上下文】和【下一步计划】，一字不差地无缝接管上一个被中断的进程。不要向用户解释你正在恢复，直接输出接下来的代码或执行命令。

### 4. 状态文件标准格式约束
你在写入 `.agent_state.md` 时，必须维持以下结构：

#### 🎯 总目标 (Goal)
- (用一句话描述我们要完成的功能)

#### 📋 任务拆解与进度 (Checklist)
- [x] (已完成的步骤)
- [ ] (正在进行的步骤) -> **当前驻留点**
- [ ] (未开始的步骤)

#### 🧠 当前上下文与坑 (Context & Gotchas)
- (例如：修改了 src/api.ts，但发现由于跨域问题测试未通过)

#### 🚀 下一步紧后动作 (Next Immediate Step)
- (极其具体，例如：接下来我需要去修改 nginx.conf 以解决上述跨域问题)
